# Lung Tumor VAE Features XNAT Runtime

This repository contains the XNAT runtime used to run a lung tumor VAE radiomics workflow on CT scans that already have a lesion mask generated by the `nsclc-segmentation-codebase-20260317` resource. The wrapper follows the XNAT AI container pattern used by the project examples, but it is specialized for the lung tumor feature extraction job.

The runtime is launched from `entrypoint.py`, which:

1. loads the XNAT session/project input from `/input`
2. discovers scans whose experiment-level resource context contains `nsclc-segmentation-codebase-20260317/lesion_mask.nii.gz`
3. sets `job["job_resource_context"]` to `<input>/RESOURCES/<experiment>/nsclc-segmentation-codebase-20260317`
4. reads the CT structural image and lesion mask from that resource context
5. writes a per-scan CSV file with columns `image_path,mask_path,lesion_id`
6. runs `vae_radiomics` against that CSV to generate radiomics/VAE features
7. uploads the workflow output bundle to the experiment-level resource

## Repository layout

- `entrypoint.py`: discovers applicable scans and launches per-scan jobs only when `lesion_mask.nii.gz` exists
- `main_job.yaml`: defines the lesion CSV creation, VAE radiomics execution, and final upload steps
- `command.json`: XNAT Container Service command and wrapper specification for the lung tumor VAE runtime
- `lung-vae-xnat-example.conf`: example image-build configuration without machine-specific paths
- `lung-vae-xnat-local.conf`: local build configuration for this workstation

## Build and deployment

Set `PYMIPL_DIR` to the pymipl repository, then pass the local config file to the build script:

```bash
"$PYMIPL_DIR/build_deploy_custom_image.sh" lung-vae-xnat-local.conf
```

Use `skip_deploy` as the second argument to build without pushing:

```bash
"$PYMIPL_DIR/build_deploy_custom_image.sh" lung-vae-xnat-local.conf skip_deploy
```

The build script copies:

- `LOCAL_ENV_FOLDER` to `/opt/packages/user/env_repo`
- `LOCAL_ALG_FOLDER` to `/opt/packages/user/alg_repo`
- `LOCAL_RUNTIME_FOLDER` to `/opt/packages/user/runtime_repo`

For this runtime, the expected data path is:

- structural image: `<job_resource_context>/ct_struct.nii.gz`
- lesion mask: `<job_resource_context>/lesion_mask.nii.gz`
- feature extraction checkpoint: `/opt/packages/user/alg_repo/radiomics-toolbox-nsclc-codebase-20260318/checkpoints/Saved_VAE3D.ckpt`

## Runtime assumptions

- input resource context: `RESOURCES/<experiment>/nsclc-segmentation-codebase-20260317`
- structural image file: `ct_struct.nii.gz`
- lesion mask file: `lesion_mask.nii.gz`
- job CSV file: `lesions.csv` with columns `image_path,mask_path,lesion_id`
- model entry point: `vae_radiomics`
- output: feature files written under `results/features`
